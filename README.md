Unity 학원 팀 프로젝트 
네오위즈 현업 개발자,전파진흥협회 심사위원 심사 전체 6팀 중 최우수 프로젝트상 수상

게임 개요
1명의 Host(대죄인 역할)와 4명의 플레이어가 비대칭 구도로 대결하는 PVP 게임입니다.
처음에는 다수의 몬스터를 사냥하는 PVE로 기획되었으나, 기획 회의 중 1대4 비대칭 구도가 더 다양하고 재미있는 경험을 줄 수 있다는 판단 하에 PVP로 방향을 전환했습니다.

팀 구성 및 담당 범위

담당자: 영역

본인 : 스폰 시스템, 구역 제한/봉인 시스템, 네트워크 동기화(FSM·호스트 권위 모델), 제단·아이템 상호작용, 로고·UI 리소스 일부
팀원(2안) : 캐릭터 비주얼·애니메이션, 전투 연출, 스킬 시스템 / 기획, 발표, 문서 제작
-아래 문제 해결 사례는 모두 본인이 직접 설계,구현한 부분입니다. 스킬 시스템 등 팀원 담당 영역은 다루지 않습니다.

문제 해결 사례

1. 호스트 권위 모델 & FSM 기반 상태 동기화

문제: 데디케이티드 서버 없이 1대4 비대칭 대전을 진행해야 했고, 5인의 캐릭터 상태를 실시간으로 맞춰야 했는데 클라이언트마다 상태가 어긋나는 문제가 반복됐습니다.

해결: 모든 상태 전이를 FSM(`AIState` enum 등)으로 구조화하고, Host가 서버 역할을 겸하는 호스트 권위 모델을 도입해 최종 판정을 Host가 전담하도록 했습니다. 상태를 하나의 `NetworkVariable`로 두어 동기화 데이터를 단순화했습니다.

2. Host ClientId(0) 충돌 버그

문제: Unity Netcode(NGO)에서 Host의 ClientId는 항상 0으로 고정됩니다. 제단 UI 권한을 담는 변수의 초기값(ulong 기본값 0)이 이 값과 겹쳐, 아무도 상호작용하지 않았는데도 Host에게 UI 권한이 있는 것처럼 잘못 판정되는 버그가 발생했습니다.

해결: 실제 ClientId로는 나올 수 없는 `ulong.MaxValue`를 기본값으로 사용해 "비어 있음"과 "점유 중"을 명확히 구분했습니다.

3. 구역 봉인 시 오브젝트 정리 (30초 유예 & Bounds 판정)

문제: 구역이 제한 구역으로 봉인되면 몬스터·상자·어린양·토템이 사라져야 하는데, 즉시 삭제하면 유저 입장에서 눈앞의 오브젝트가 갑자기 사라지는 부자연스러움이 있었습니다.

해결: 구역별 스폰 오브젝트를 리스트로 추적해두고, 봉인 이벤트 발생 후 30초 유예 코루틴을 실행해 해당 구역의 실제 Bounds 범위 안에 있는 오브젝트만 판별해 정리했습니다. 유예 시간 동안 스스로 이동해 구역을 벗어난 오브젝트는 정리 대상에서 자동 제외됩니다.

4. 네트워크 동기화 전략 — 정확성 vs 반응성

동기화 대상을 성격에 따라 두 갈래로 분류했습니다.

-구분 : 처리 방식

캐릭터 위치/이동 (반응성 우선) : 클라이언트 선반영 + Host 확정값으로 Lerp 보정
상태 전이·아이템 상호작용 (정확성 우선) : Host 확정 후에만 반영, 클라이언트는 요청만 전송 

5. 이벤트 기반 결합도 분리

구역 봉인처럼 여러 시스템이 하나의 사건에 반응해야 하는 경우, 
`OnZoneSeal` 같은 공용 이벤트를 발행해 구역 제한 시스템과 
스폰 관리 시스템이 서로의 내부 구현을 몰라도 각자 독립적으로 반응하도록 설계했습니다.
